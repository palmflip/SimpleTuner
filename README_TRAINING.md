# Тренировка Flux LoRA на H100 SXM - Руководство

Это руководство поможет вам настроить и запустить тренировку LoRA для модели Flux на мощном железе H100 SXM с оптимальными настройками производительности.

## 🚀 Быстрый старт

### 1. Подготовка на локальной машине

Склонируйте репозиторий и подготовьте датасет:

```bash
git clone https://github.com/your-repo/SimpleTuner.git
cd SimpleTuner
```

### 2. Подготовка датасета

Создайте папку `dataset` и поместите туда:
- Изображения: `1.jpg`, `2.jpg`, ..., `50.jpg`
- Описания: `1.txt`, `2.txt`, ..., `50.txt`

```
dataset/
├── 1.jpg
├── 1.txt
├── 2.jpg
├── 2.txt
└── ...
```

**Требования к изображениям:**
- Разрешение: минимум 1024x1024 пикселей
- Формат: JPG, JPEG или PNG
- Качество: четкие, без размытия
- Содержание: реалистичные фотографии персонажа

**Требования к описаниям:**
- Формат: обычный текст в .txt файлах
- Язык: английский
- Содержание: детальное описание изображения
- Длина: 50-200 слов

### 3. Перенос на арендованное железо

Скопируйте весь проект на сервер с H100:

```bash
# На арендованном сервере
git clone https://github.com/your-repo/SimpleTuner.git
cd SimpleTuner
```

Убедитесь, что базовая модель находится по пути:
```
/workspace/models/unet/flux/fluxmania_V.safetensors
```

### 4. Запуск тренировки

```bash
./train_flux_h100.sh
```

## ⚙️ Конфигурация

### Основные параметры (config/config.json)

- **Batch Size**: 8 - оптимально для H100 SXM
- **Learning Rate**: 8e-5 - проверенная ставка для Flux
- **LoRA Rank**: 32 - баланс качества и размера
- **Resolution**: 1024x1024 - натив разрешение Flux
- **Target Layers**: "all" - все attention слои
- **Precision**: bf16 - оптимально для H100
- **Optimizer**: adamw_bf16 - быстрый и эффективный
- **Scheduler**: cosine_with_restarts - плавное снижение LR

### Специфичные для Flux параметры

- **flux_lora_target**: "all" - тренируем все слои attention
- **flux_guidance_mode**: "constant" - постоянное значение guidance
- **flux_guidance_value**: 3.5 - оптимальное значение для CFG
- **flow_matching_loss**: "compatible" - совместимый режим потерь
- **t5_attention_mask**: true - маскирование паддинга в T5

### Оптимизации для H100

- **torch_compile**: включен с режимом "max-autotune"
- **allow_tf32**: включен для ускорения
- **gradient_precision**: fp32 - максимальная точность
- **dataloader_num_workers**: 8 - параллельная загрузка данных

## 📊 Ожидаемые результаты

### Время тренировки
- **50 изображений**: ~33 минуты на H100 SXM
- **2000 шагов** (40 повторений на изображение)
- **Скорость**: ~1.0 сек/шаг

### Использование ресурсов
- **VRAM**: ~65-70GB из 80GB H100 SXM
- **System RAM**: ~32GB 
- **Disk I/O**: умеренное (кэширование включено)

### Качество результата
- Высокое качество изучения персонажа
- Хорошая генерализация на новые позы
- Сохранение деталей лица и одежды
- Совместимость с CFG inference

## 🔧 Настройка под ваши потребности

### Для меньшего количества изображений (10-30)

Измените в `config/config.json`:
```json
"--learning_rate": "1e-4",
"--max_train_steps": 1200
```

### Для большего количества изображений (100+)

```json
"--learning_rate": "6e-5",
"--max_train_steps": 4000,
"--lr_warmup_steps": 400
```

### Для экспериментальной тренировки

```json
"--train_batch_size": 16,
"--lora_rank": 64,
"--checkpointing_steps": 100
```

## 🚨 Устранение проблем

### Out of Memory (OOM)
Уменьшите batch size:
```json
"--train_batch_size": 4
```

### Медленная тренировка
Проверьте оптимизации CUDA в скрипте `train_flux_h100.sh`

### Плохое качество результата
- Проверьте качество исходных изображений
- Улучшите описания в .txt файлах
- Увеличьте количество шагов тренировки

### Модель не сходится
- Уменьшите learning rate до 4e-5
- Увеличьте warmup steps
- Проверьте консистентность датасета

## 💡 Best Practices

1. **Качество данных > Количество**: Лучше 30 отличных изображений, чем 100 посредственных
2. **Разнообразие поз**: Включите различные углы, освещение и выражения
3. **Консистентность стиля**: Все изображения должны быть в одном стиле (реалистичные фото)
4. **Детальные описания**: Чем подробнее описания, тем лучше результат
5. **Мониторинг процесса**: Следите за логами и validation samples
